# Architecture

Conciliado has three layers: an off-chain client in the payer's browser, contracts on Arc
mainnet, and a build pipeline that runs on the developer machine. There is no application
server and no server-held key. The payer's wallet signs every transaction.

## Mainnet, testnet, off-chain split

| Component | Where | Why |
| --- | --- | --- |
| `PayoutBatch` contract (the shipped one) | Arc mainnet (chain 5042) | The proof: real USDC moves, real fees are paid. Deployed with Arc Foundry from the source pulled out of Arc Studio, unchanged. |
| Demo batches | Arc mainnet | The demo pays and rebuilds a real batch. |
| Studio iterations of `PayoutBatch` | Arc testnet | Arc Studio deploys to testnet only. Iterations, audit turns, and test runs happen here. |
| Payer app (React, Vite, wagmi, ConnectKit) | Off-chain, static build in the payer's browser | No backend is needed. Reads go straight to Arc RPC. |
| Invoice CSV with invoice ID and salt | Off-chain, browser memory only | The chain stores only an opaque `bytes32` reference per line. The mapping from invoice to reference stays with the payer. |
| Ledger rebuild and USDC tie-out | Off-chain, in the browser | Built from logs, receipts, and balances read from Arc RPC. |
| Keys | The payer's wallet | Nothing in this project holds or sees a private key. |
| Servers and databases | None | Nothing to host, secure, or trust beyond the chain and the RPC endpoint. |

## Things to keep in mind

- Gas on Arc is paid in USDC. The native balance uses 18 decimals and the ERC-20
  interface uses 6, so the rebuild has to normalize units before the tie-out
  ([spike](spikes/arc-studio-path.md)).
- `PayoutBatch.payBatch` reverts unless every payee is on the payer's allow-list, so
  `addPayees` runs before the first batch for a new payee.
- `PayoutBatch` holds no funds. Each line is `transferFrom(payer, payee, amount)`.
- The rebuild and the app are described here as designed. They are built in issues #7,
  #12, and #13.
